# P2.5 — Web/UI safe API surfaces

> **Superseded (2026-11-12):** the safe-by-default wave removed the
> `::safe::` / `safe_page_*` spellings described below. The names in this file
> are the historical P2.5 spellings; see `BREAKING.md` for the current surface
> (`window::Window`, `webview::WebView`, `page::escape_js`,
> `router::set_request`, `server::serve_static`, `components::*`).

Status: additive safe surfaces implemented for `window`, `webview`, `page`,
`components`, `router`, and `server`. The legacy raw APIs are unchanged, so
existing callers keep compiling.

## Implemented (new files)

| Library | File | Public safe surface |
|---|---|---|
| page | `lang/libs/page/src/safe.ch` | flat top-level `safe_page_escape_html(&str)`, `safe_page_escape_html_view(string_view)`, `safe_page_escape_js(&str)`, `safe_page_escape_json(&str)`, `safe_page_append_html(page, &str)`, `safe_page_append_js(page, &str)`, `safe_page_append_html_escaped`, `safe_page_append_js_escaped`, typed `safe_page_set_parameter<T : SafePageParam>(page, &str, &T)`, `safe_page_get_parameter_safe(page, &str) : Option<string>` |

| router | `lang/libs/router/src/safe.ch` | `router::safe::set_request(page, method, path, query, body)` (page-owned copies), `get_request(page) : Option<RequestInfo>`, `query(page, key) : Option<string>`; `RequestInfo` owns every field |

`components` had no raw-pointer public surface before this change; its
`#universal` declarations are compile-time macros. The new helpers are the
runtime text/theme calls an app author makes directly.

## Design notes / blockers

- **No `HtmlPage::append_html(&str)` method.** Chemical has no function
  overloading and external/generic inherent impls are not supported, so a
  one-argument method cannot coexist with the legacy
  `HtmlPage::append_html(*char, size_t)`. The additive safe equivalent is the
  flat top-level function `safe_page_append_html(page, &str)` (same for
  `safe_page_append_js`). The functions are deliberately NOT wrapped in a
  namespace named `page`: that shadows the module name and makes the html/css
  CBI plugins fail with `'append_html_char' function is required on 'page'`.
- **Callback state is heap-backed.** Both safe handles hold a private pointer to
  a heap state object, so the address registered as native user data never moves
  when the handle is returned/stored by value. `off_*` marks the handler
  inactive; captures are released when the window/webview state is destroyed
  (actual early release is a tracked improvement). The destructor quiesces by
  destroying the native window/webview before freeing the state.
- **`!Send`/`!Sync`.** `window::safe::Window` has an explicit negative impl;
  `webview::safe::WebView` is structurally `!Send`/`!Sync` (raw state pointer).
  Negative tests pin both (`lang/tests/negative/src/p25_web_ui.ch`).
- **GUI coverage.** `lang/tests/webview/src/safe_api_compile.ch` type-checks
  every safe method. The real WebView suite also runs in this environment
  (`--webview` 51/51) and the universal suite runs 368/368. Machines without
  GTK3 + WebKit2GTK + a display still fall back to the compile-only surface.

## Tests

- `lang/tests/libs/page/src/safe_api.ch` — HTML/JS/JSON escaping, XSS payloads
  (`<script>`, `'`, `\`, `</script>`), raw append parity, typed parameter
  formatting/round-trip. **6/6 pass in the real `--libs` suite.**
- `lang/tests/libs/router/src/safe_api.ch` — owned request round-trip, missing
  request, query values (including present-but-empty and absent). 3/3 passed in
  a focused page+router harness.
- `lang/tests/webview/src/safe_api_compile.ch` — compile-only window/webview
  surface (all methods, callbacks, bridge); passes `--check`.
- `lang/tests/server/src/safe_api_compile.ch` — compile-only server surface;
  passes `--check`.
- `lang/tests/negative/src/p25_web_ui.ch` — `Window`/`WebView` rejected under a
  `T : Send` bound; both PASS in `--negative`.

## Environment / unrelated blockers observed

- The page safe surface initially lived under `public namespace page`; that
  shadowed the module name and made the html/css CBI report
  `'append_html_char' function is required on 'page' for html to work`. It was
  rewritten as **flat top-level `safe_page_*` functions**; the libs `--check`
  and a focused page+html_cbi+css_cbi module then passed.
- Concurrent edits to unrelated untracked files (`lang/libs/lab/src/safe_api.ch`,
  `lang/libs/test_env/src/safe_api.ch`, `lang/libs/compiler/src/api.ch`) come
  and go during this work. At the time of the successful libs `--check` and the
  page 6/6 run they were clean; a later `lab/src/safe_api.ch` edit
  (`SAFE-UNSAFE-001` at lines 55/62/69/86/93) can make `--libs --check` red
  again. That failure is outside this task's files.
- The GUI safe surface is compile-verified only; no display is available.
