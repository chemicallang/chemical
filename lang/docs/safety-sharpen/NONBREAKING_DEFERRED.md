# Safety Sharpen — deferred to the breaking branch

Items on the Phase 3 worklist that **cannot** be implemented without rejecting
code that compiles today, removing/renaming a public API, or otherwise breaking
the stable safe-API release. Each entry states the reason and the intended
breaking-branch task. Additive work stays in the main branch.

Status: P3.1 added the synchronous effect checker, module policy defaults and
generic propagation without breaking existing code. The remaining items below
need either a semantics decision or a breaking diagnostic.

| Item | Why deferred | Breaking-branch task |
|---|---|---|
| **P3.1 async effect propagation** | An `async func` lowers to a coroutine ramp plus generated poll/drop/resume functions. The ramp always allocates a frame (`[no_alloc]` is inherently impossible), its div-zero/OOM guards are compiler-generated aborts, and `await` reaches the child through generated poll calls. Attributing those operations to the source effect set is a coroutine-specific analysis, not the call-site bitset the synchronous checker uses. Today an effect annotation on an async function is rejected explicitly instead of being silently ignored. | Add an async-effect model: annotate the frame allocator as an alloc effect, treat compiler-generated guards as part of the allocation effect, and prove `await` through the child's `FutureHandle` contract. Then accept `[no_panic]`/`[no_unsafe]`/`[no_blocking]` on async functions and test TCC+LLVM. |
| **P3.1 module defaults on plugin-generated declarations** | The `chemical.mod` policy is applied after parsing. Functions that CBI macros add during symres/generics (for example `#json` impls) are created later and therefore keep their explicit attributes only. Applying the policy to them requires threading the module policy into the CBI/macro emission boundary. | Thread the module effect policy into `ASTBuilder`/macro emission so a generated function inherits the default, with a macro regression test. |
| **P3.1 `[no_panic]` on generic `vector::try_*` / `string` growth** | `try_reserve` calls the unannotated `malloc`/`realloc`; the compiler emits `__chc_div_zero_fail` for the element-size division even after the `elem_size == 0` branch proves it nonzero; `try_push` also runs the generic `T` destructor, whose effect set is unknown for an unbounded `T`. Annotating these now would either be unsound or require a false proof. | 1) annotate audited libc externs (`malloc`/`realloc`/`memcpy`) `[no_panic]`; 2) elide the div-zero guard for a provably nonzero divisor; 3) add an effect bound for destructors (`T: NoPanicDrop`) or make `try_push` return before constructing `T`'s drop glue. Then annotate the `try_*` family. |
| **P3.1 `[noreturn]` enforcement** | `[noreturn]` is accepted as a documented property but has no checker: a function that falls through does not yet error. This is a new rejection, not a widening. | Add a divergence check at MIR lowering for declarations carrying `noreturn`, with tests for `return`, fallthrough and `panic`/`unreachable` bodies. |
| **P3.3 `regex::Regex` temporary codegen workaround** | `lang/tests/regexp/helpers.ch` binds every `regex::compile(...)` result to a local because a temporary `Regex` in an expression corrupted the heap under the C backend. The cause is temporary lifetime/drop ordering in MIR (the temporary is destroyed while a borrowed method receiver is still live); a fix changes drop scheduling for every temporary, so it needs the reject-or-fix decision the breaking branch owns. | Add a MIR temporary-lifetime regression (`regex::compile("a").is_match(...)`) and fix drop scheduling so a temporary borrowed as a receiver lives through the call. Remove the helper note after the suite passes with temporaries. |
| **P3.4 `&raw local[0]` out-buffer codegen workaround** | `lang/libs/tls/src/raw.ch` writes output into struct fields instead of `&raw local[0]` for large-stack functions: the address of an array local is miscomputed at large stack offsets in the C backend. Fixing it is a stack-layout/frame-offset bug in MIR/emission, not an API issue; it needs a dedicated frame-layout regression and therefore is not a safe blind change in the additive wave. | Add a MIR/frame-layout regression with a large-stack function taking `&raw mut local[0]`, fix the offset calculation, then replace the TLS struct-field workaround with the direct out-buffer call. |
| **P3.3 direct-reference return loan** | A call returning a *direct* reference only carries a loan when the callee's function type spells the reference in return position. Tracking it for every safe callee rejects valid code today because an escaped loan in one `return` branch is not path-sensitive (a later `&mut` conflicts). The fix is a borrowing-model change, not an additive bug fix. | Make escaped loans path-scoped, then classify direct-reference returns and reject an escaping direct reference with `SAFE-BORROW-001`; add the false-positive case from the html tokenizer to the positive suite. |
| **P3.3 pattern-bound variant payload field move** | Moving a field out of a variant payload bound by a pattern (`var Some(v) = opt; v.field`) is still rejected with `SAFE-MOVE-004`. Allowing it safely requires tracking the payload's drop flag through the pattern binding and is a rejection-only widening of the move checker; the safe alternative is an explicit `take`/`ManuallyDrop` API. | Extend the move/drop-flag analysis to pattern-bound payload fields and add both a positive test and the still-rejected partial-move cases. |
| **P3.3 remaining HRTB/async type-erasure shapes** | Source-to-stored/opaque/unsized HRTB cases and type erasure performed inside a non-`unsafe` generic container are rejected by `SAFE-LIFE-005`; accepting them requires a richer region/erasure model. The explicit `unsafe` boundary remains the documented escape hatch. | Add representation for erased lifetime-carrying containers and prove the consumer contract; keep the explicit-`unsafe` path as the audited fallback. |
| **P3.7 raw-surface audit offenders** | `scripts/safety-raw-surface-audit.py` reports four pre-existing non-breaking offenders: `universal_cbi` `body_check`/`hydration_check_body`, `web::App::handle`, and `webserve::serve`. They accept caller raw pointers while declared safe. Making them `unsafe func` (or taking a view/wrapper) is a public-breaking change, so it cannot land on this branch; they are not in the reviewed `::raw` allowlist (they are not raw-named, they are raw-typed safe entry points). | Convert each to `unsafe func` or a checked owning/view parameter and update every caller; add the regression to the raw-surface gate. |
| **P3.6 4 MB goal (341,432 B remaining)** | Current Release TCCCompiler is 4,341,432 B (hard 5 MB ceiling met). The `-Os` experiment reached 2,793,528 B but raised the sample compile from 318–382 ms to 427 ms, which violates the compile-time non-regression rule. Reaching 4 MB without that trade needs code removal, not a blanket optimization flag. | 1) Implement the generic runtime drop-path descriptor replacing per-dimensional array selectors (keep constant-index fast paths), then re-measure. 2) Apply `-Os` only to non-native-hot translation units (JS emitter, interpreter/comptime helpers) and keep `-O3` for lowering/type-checking; verify sample compile time. 3) Profile and trim the largest objects (`ASTProcessor`, `MIRLowerCall`, `LabBuildCompiler`). |
