## cmap format-4 fix

The parser now uses the spec layout:

```
endCode       = base + 14 + 2*i
startCode     = base + 16 + 2*segCount + 2*i
idDelta       = base + 16 + 4*segCount + 2*i
idRangeOffset = base + 16 + 6*segCount + 2*i
glyph address = idRangeOffset_slot + idRangeOffset + 2*(cp - startCode)
```

| Oracle | Before (P0.1 blocker) | After |
|---|---|---|
| DejaVuSans `A` U+0041 | 60189 | **36** |
| DejaVuSans `é` U+00E9 | 60357 | **171** |
| Liberation Sans `A` / `é` | wrong (same bug) | **36 / 171** |
| synthetic format-4 `A` / `é` | — | **2 / 3** |
| `中` / emoji on pinned font | wrong / not covered | **missing glyph (glyph 0)** |

The synthetic font is built in the test with different A/é glyph IDs, so a
regression in the segment-array offsets cannot pass accidentally. The test
also checks a Level-1 `glyphIdArray`-free/sentinel mapping and missing glyph.

## TextContext semantics

- Font size scales raw advances/metrics by `style.size / units_per_em`.
- `ascent`, `descent`, `line_gap`, `cap_height`, `x_height` come from the font
  tables. The line box is `max(font_ascent + font_descent + font_line_gap,
  style.size * style.line_height)`; extra style leading is split as half-leading
  for `first_baseline`.
- Empty text: `width=0`, `height=0`, `lines=0`.
- Missing glyph: fixed 0.5em fallback advance, never an error/panic.
- `max_width` wraps at spaces; `max_lines` sets `truncated`; no ellipsis glyph is
  painted yet. `NoWrap` ignores `max_width`. Non-finite sizes/line heights/limits
  clamp to finite fallbacks; `units_per_em == 0` is rejected at load.
- Tabs use `constraints.tab_size` (then style tab size, default 4) times the
  space advance.
- `measure_rich` sums the per-span advances and takes maximum vertical metrics;
  no shaping, kerning, bidi or span-specific font selection yet.
- No rasterization, atlas, shaping, GSUB/GPOS, or outline consumption in this
  packet.
