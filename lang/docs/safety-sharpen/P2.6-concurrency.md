# P2.6 — Safe concurrency surfaces

Status: safe additive APIs implemented and tested; the exact
`for<'s> (&'s mut Scope<'s>) => void` `thread::scope` surface remains blocked on
the checker and is **not** shipped.

## Implemented

### `std::thread`

Already present and kept as the safe entry points:

- `spawn<T, U>(f : (value : T) => U, arg : T) : JoinHandle<U>` where
  `T : Send + 'static, U : Send + 'static`.
- `spawn_closure<U, C>(f : %capture<() => U, ..., C>) : JoinHandle<U>` where
  `C : Send + 'static, U : Send + 'static`.
- `JoinHandle<T>`: owning handle, `join() -> T`, destructor joins exactly once;
  `Send + Sync` when `T : Send`.
- `scoped_spawn*` / `scoped_run*` / `ScopedScope<T>` / `ScopedClosureScope`
  remain the audited join-before-return scoped forms.

### `std::concurrent.ThreadPool`

- `create_pool(n)` returns an owning `ThreadPool` (`Send + Sync`), no public raw
  pool fields (`PoolData` state is `internal`).
- `submit_fn<U>(f : () => U) : Future<U>` where `U : Send` — safe non-capturing
  submission. The wrapper captures only the function pointer.
- `submit_void_fn(f : () => void)`.
- `submit_closure(closure, &pool) : Future<T>` remains the safe capturing form
  (`C : Send + 'static, T : Send`).
- `Future<T>::get()` is the owning consumer; dropping an un-consumed future is
  safe and frees the promise.

### `std::Mutex` / `std::RwLock` / `std::Condvar`

- `Mutex<T>` / `RwLock<T>` safe constructors and guard APIs were already
  present. Guards stay `!Send + !Sync`.
- New `Condvar` (`std::new_condvar()`):
  - `MutexGuard<T>::wait(&cv)` and `wait_timeout(&cv, ms) : bool`.
  - `Condvar::notify_one()` / `notify_all()` take `&self`.
  - Free helpers `std::condvar_wait(&cv, &mut guard)` and
    `std::condvar_wait_timeout(&cv, &mut guard, ms)`.
  - `unsafe impl Send/Sync for Condvar` (native condvar is cross-thread; the
    guard passed to `wait` is still `!Send`).

### `async` executor

- `Executor`, `RawTask`, `TaskVTable`, `JoinState<T>`, `SpawnTask<T>`,
  `ChannelShared<T>`, `ChannelNode<T>`, `RecvState<T>`, and
  `BlockingState<T>` now keep their state `internal`. Safe code can name the
  types but cannot read or forge their fields.
- New `async::executor_drive(max : uint) : uint` — safe driver for native event
  loops. The raw entry points (`executor_poll_tasks`, `exec_enqueue_task`,
  `exec_make_waker`, `executor_set_wake_hook`, `executor_wait`) remain
  `unsafe` and are used only by the runtime/UI backends.
- `spawn`, `spawn_local`, `spawn_blocking` remain explicit `unsafe` boundaries
  because their frames have erased captures; `spawn_send` /
  `spawn_send_handle` are the checked cross-thread forms.

## `thread::scope` spike (blocked, not shipped)

The planned shape was:

```chemical
public struct Scope<'a, T> {
    internal var value : &'a T
    internal var threads : [32]*mut std::concurrent.Thread
    internal var count : size_t
}

public func <T> scope(value : &T,
                      body : for<'a> (scope : &'a mut Scope<'a, T>) => void)

public func <T, C> scope_spawn(
    s : &mut Scope<T>,
    f : %capture<(value : &T) => void, std::default_function_instance, C>
) where C : Send, T : Sync
```

Findings from `lang/compiled/p26_scope_spike` and
`lang/compiled/p26_scope_unwhitelisted` (TCCCompiler `--check`, 2026-11-07):

1. The higher-ranked body type parses and a **named** lifetime-generic body is
   accepted:
   `func <'b> body_impl(s : &'b mut Scope<'b, int>)` passed to
   `for<'a> (&'a mut Scope<'a, T>) => void` compiles.
2. An **anonymous lambda** body does not satisfy the higher-ranked contract:

   ```
   [TypeCheck] error[SAFE-BORROW-099]: function value does not satisfy the
   higher-ranked lifetime contract of type '(scope : &a mut Scope<a, int>) => void';
   an elided or generic lifetime is required, not a concrete one
   ```

3. A generic **method** `Scope::spawn<C>` cannot infer the capture witness from
   a lambda argument:

   ```
   [SymRes:link] error: couldn't infer type for generic parameter at index 0,
   no default type has been given
   ```

   (This is why every existing scoped API is a free function.)

4. A **new** free-function name (e.g. `scope_spawn`) is not in the compiler's
   hardcoded scoped-capture whitelist (`TypeVerify.cpp`, around
   `scoped_capture_call`), so a borrowed capture is rejected:

   ```
   [TypeCheck] error[SAFE-UNSAFE-002]: creating a callback that captures
   function-local storage by reference requires an unsafe boundary until typed
   capture tracks the referent lifetime
   ```

   A non-capturing lambda passed to the same `%capture` parameter also fails:

   ```
   [TypeCheck] error: value with type '(value : &int) => void' does not satisfy
   type '%capture<(value : &T) => void,default_function_instance>'
   ```

Decision: keep `@scoped_callback` and the existing `scoped_*`/`scoped_run*`
surface. Shipping a new `thread::scope` under a new name would require (a)
closure HRTB satisfaction for `&'s mut Scope<'s, T>` parameters, (b) capture
witness inference on the method/free entry point, and (c) extending the
scoped-capture whitelist to the new name. None of that is faked here.

## Tests

- `lang/tests/libs/thread/tests.ch`: safe `spawn_closure`, `ThreadPool`
  `submit_fn`/`submit_void_fn`/`submit_closure`, `Mutex` try-lock/drop-unlock, `RwLock`
  read/write/try-write conflict, protected-value drop exactly once, `Condvar`
  notify/timeout (both `guard.wait(&cv)` and the free `condvar_wait_timeout`),
  and a generic scoped closure with no `@scoped_callback`.
- `lang/tests/libs/async/pin_future_safe_test.ch`: `Pin` `get_ref`/`get_mut`/
  `into_inner`/`Unpin` bound, `!Unpin` pinned read, `spawn_send` owned frame,
  `SendFutureHandle` moved to a worker, cancellation dropping a suspended
  local exactly once, and the safe `executor_drive` facade.
- Existing negative tests cover `MutexGuard`/`RwLock` guards as `!Send`,
  `lock_guard`/`recursive_lock_guard` as `!Send`, and `async::Executor` as
  `!Send`.
